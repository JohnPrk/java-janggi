# java-janggi

장기 미션 저장소

## 실험 1

### 장기판은 어떤 자료구조로 표현할 것인가?
* Map<Coordination(좌표), Piece(기물)>의 형태로 표현할 것입니다.
* 처음에는 장기판의 궁성의 이동 가능 방향이나 좌변이나 우변의 이동 가능 방향 등의 연결을 위해서 ‘연결 리스트’를 생각했는데 차나 포 같은 경우에 인접이 아닌 연결 리스트의 탐색이 어렵게 느껴져서 Map 자료구조를 사용했습니다.

### 기물은 어떤 정보를 가지는가?
* 기물은 진영의 값을 표현하는 래퍼 클래스Team을 가지고 있습니다.

### 위치 정보는 누가 관리하는가? (보드? 기물?)
* 위치 정보는 장기판인 Board가 관리합니다.

### 빈 칸은 어떻게 표현하는가?
* EmptyPiece 객체를 만들어서 null 안정성을 지키면서 빈 칸의 빈 기물을 표현할 수 있을 것 같습니다.

* 궁 : 8개

* 포 : 4개
* 마 : 8개

* 사 : 8개
* 졸/병 : 8개

### 예상되는 조건문 개수
* 68가지

### 가장 복잡한 기물의 이동 규칙
* 포
    * 반드시 기물을 한 개 뛰어넘어야만 그 방향으로 이동이 가능하다.
    * 이때 넘는 기물은 피아를 구분하지는 않으나, 같은 포를 넘거나 잡을 수는 없다.
    * 궁성 내에서 차와 마찬가지로 대각선을 따라 이동 가능하다.

## 실험 4

### 새 기물 추가 시 수정해야 하는 곳은?
* 자기 자신

### 기존 기물 규칙 변경 시 영향 범위는?
* 자기 자신

### 조건문이 한 곳에 모여 있으면 생기는 문제는?
* 새 기물이 추가되거나 기물 규칙이 수정될 때 수정을 해야하는데, 이 때 휴먼 에러가 발생하기 쉽다.

### 조건문 없이 이동 규칙을 처리하는 방법은?
* 움직임이는 행동을 가진 객체를 추상화하여 부모 클래스를 만들고 이를 상속 받아서 실제 움직임 규칙은 자식 클래스에서 하도록 한다.

설계 결정 이유

1. Piece 인터페이스 + AbstractPiece 추상 클래스를 도입한 이유
   * team 필드가 모든 기물 공통이므로 AbstractPiece에서 관리
   * 기물별 이동 규칙만 각 구체 클래스에 구현(OCP)
   * 조건문 없이 movablePositions() 다형성으로 처리

2. Board 추상 클래스를 도입한 이유
   * 현재 요구사항(SimpleBoard)과 인터랙티브 요구사항(InteractiveBoard) 분리
   * 위치 관리 방식이 바뀌어도 Game은 영향 없음 (OCP)

3. PlacementStrategy 인터페이스를 도입한 이유
   * 마·상 초기 배치 선택 기능을 나중에 추가할 때 Board 수정 없이 전략만 추가 (OCP, DIP)
   * 현재는 DefaultPlacement만 구현

4. EmptyPiece를 도입한 이유
   * null 대신 빈 칸을 객체로 표현 (널 객체 패턴)
   * NPE 없이 isEmpty()로 빈 칸 여부 확인


### 상태 관리 책임에 대한 내 의견
* 변하는 것(기물 배치)은 Board가, 변하지 않는 것(좌표, 기물)은 불변 객체로 분리한다
* 위치 정보는 기물이 아닌 Board가 관리한다
  * 기물이 위치를 가지면 이동 시 내부 상태가 변해 불변 설계가 불가능하고, 특정 위치 조회 시 전체 순회가 필요하다
* Board만이 상태를 변경할 수 있으며, 외부에는 조회만 허용한다 (캡슐화)

### 예상 조건문 개수와 문제점
* 각 기물 이동 규칙 합산: 약 68개

### 문제점
* 새 기물 추가 시 68개의 조건문을 모두 찾아서 수정해야 한다
* 수정할 곳이 흩어져 있어 누락이 발생하기 쉽다
* 한 메서드나 클래스에 모든 분기가 집중되어 가독성이 떨어진다
* 단일 책임 원칙 위반: 한 클래스가 모든 기물의 이동 규칙을 알게 된다


### 조건문 없이 처리하는 방법에 대한 아이디어
* Piece 인터페이스에 `movablePositions(Coordination, Board)` 메서드를 정의하고
  각 기물 구현체가 자신의 이동 규칙을 스스로 구현한다 (다형성)
* 기물 분기 조건문 7개가 사라지고, 이동 규칙은 각 클래스 안으로 분산된다
* 새 기물 추가 시 새 클래스만 추가하면 되고 기존 코드는 수정하지 않는다 (OCP)
* `board.movablePositions(piece)`를 호출하면 조건문 없이
  해당 기물의 이동 규칙이 실행된다
